## 3. 扩散完整预测（BR）：从设计到 H-val 采纳

1. 诊断（`20261103-215324-…-design-and-plan.md`）：上一轮 J3 多步采样的抖动来自高频带——GT 在 >2 Hz 的能量与步态频段相当、主要是拟合抖动，流把它学成样本里的抖动（单样本 dct_high 为 GT 的 21%，FD2 1%）。
2. 方法：**B** = 局部 DCT 20 → 11 阶（≤2 Hz，train oracle 代价为 FD2 mse 的 0.82%，低于 2% 回退线）；**BR** = B + t∈[0.5,1) 的去噪估计也施加 FD2 配方（采样最后一步的 x̂ 就是交付的预测）。可采纳读出只有多步采样：ode0（τ=0 确定性 ODE）、median16、median16t05；端点与单样本只作参照。
3. seed0 结果（`20261103-224829-…-result.md`）：无候选过原规则；BR:ode0 只差 xyz_mse（+4.4%），mpjpe −1.81%、jerk 15.4。mse 增量 86% 来自最差 10 个窗口（选错整体走向）。
4. 用户授权 mse 门限 1.05×（`20261104-090141-…-amendment.md`）后 3 seed（`20261104-095145-…-result.md`）：**BR:ode0 mpjpe .16835（−2.24%，逐 seed −1.81/−2.42/−2.47）、mae −2.7%、mse +2.8%、jerk 15.8**，修订规则通过。附带：BR:endpoint 按原规则全过，但不是扩散生成，只记录。

## 4. 腿真正迈步：落脚规划层

1. 诊断（`scripts/diag_ntu2p_gait_oracle.py`）：**表示不是瓶颈**——GT 经 11 阶编解码仍迈步（步数 2.22、左右交替相关 −0.40）；FD2/BR 预测左右脚几乎不交替，滑行帧比约为 GT 的 6 倍。
2. 方法（`20261104-170558-…-design-and-plan.md`，`utils/ntu2p_foot_planner.py`）：不训练，模型输出后只改双腿膝/踝/脚掌：着地锁定；预测踝离锁定点 >0.16 m 且另一脚着地时抬脚；落到预测位置前方 0.10 m；弧高 0.07 m；预测踝抬高 >0.20 m 时自由；两骨 IK 重解膝。参数全部来自 train GT 步态统计（`scripts/diag_ntu2p_gt_gait_stats.py`）。
3. v1（摆动固定 21 帧）抽帧可见一字马弓步 → 不通过；原因是 NTU 脚部抖动使接触判定高估摆动时长。v2 摆动按步长自适应 5–12 帧（`20261104-171132-…-amendment.md`）。
4. 3 seed（`20261104-172148-…-result.md`）：BR:ode0 + v2 **滑行帧比 .191 → .032（GT .034）、步数 1.37 → 1.69、GT 着地帧脚速 .217 → .175、穿地 .067 → .028、mpjpe +0.3%、jerk 21.8**；"左右交替相关 ≤ −0.25"未达（−0.245）。9 段固定案例全部抽帧目视通过。
5. 用户"接受，并入主线"（`20261104-172527-ntu2p-mainline-adoption-br-ode0-foot-planner.md`）。
