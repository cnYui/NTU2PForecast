# 相位流形步态模块（PGait）：设计与预登记

## 用户要求（2026-11-07）

1. 永久去除落脚规划层，之后不再用任何不参与训练的方法（规则后处理、评价时修正）来提分或改善观感。已执行：`utils/ntu2p_foot_planner.py` 与 `eval --foot_planner` 已删除。
2. mpjpe 越低越好，同时视觉自然、脚步不漂移。
3. 用"更宏大的方式"：设计模型架构和损失函数，让模型学到更高层的关系。参考别人的论文，把思路加进现有架构，重点是脚一步一步走、不漂移。

**对照**：BR:ode0，不加规划层。
- H-val seed0：mpjpe .16911、滑行帧比 .199、步数 1.39。
- H-val 3 seed：mpjpe .16835。
- test：mpjpe .17906。

## 为什么前几轮都失败

- **确定性读出输出的是条件均值。** 未来什么时候迈哪只脚本身不确定，在姿态空间里对不同相位求平均，交替的步子就被抹平成"身体平移、脚跟着滑"。
- **逐帧压脚速的损失（FS/FC/FH/FHS）只会把脚速整体缩小**，支撑底 .13 → .06–.08 m/s，摆动峰 1.09 → .74–.85，最后变成慢挪。
- **随机读出不改变形状，还让 mpjpe 变差 2–6%。**
- **表示不是瓶颈**：GT 经同一套编解码后，步数 2.22，滑行 .045。
- **规划层证明了代价很小**：让脚落定在某个具体相位、身体保持均值，mpjpe 只增加 0.3%。所以目标是：身体（root）按均值预测，腿按一个具体的相位生成，而这个相位要由学出来的模型给出。

**不声称首创**：相位流形、接触一致性都是已有技术。本工作的内容是把它们接到双人扩散预测上，用同口径实验报告相对收益。

## 核心思路：在相位空间预测，在流形上解码

把腿的未来拆成两部分，分开学：

- **什么时候迈**：相位 φ(t)、频率 f(t)、振幅 a(t)。
  - 相位用圆周损失，频率和振幅是量值；对它们求平均都不会把摆动抹平。
  - 前几轮失败正是因为平均发生在姿态坐标上，正负相消。
- **给定相位时腿长什么样**：解码器 G。
  - 训练时喂 GT 相位（teacher forcing）。相位已知，就不存在"不确定要求平均"的问题，所以 G 学到的是清晰的步态：支撑相脚停住，摆动相快速迈出。
  - 着地概率也由 G 根据相位输出，因此是清晰的，不会像 FC 的着地头那样被抹成 0.5。

## 架构：在主线 BR 的腿部加入相位步态模块

主线中 ①–⑥（观测编码、STG 去噪器、root 和上半身）不变。原来直接回归腿部 DCT 的腿流 ⑦，改为由下面三个部件生成腿。只替换膝、踝、脚掌；髋来自主体，骨长取观测末帧。

1. **腿部周期自编码器（PAE，DeepPhase 式）**
   - 输入：每人每帧在本人朝向系下的特征，共 21 维，即膝、踝、脚掌相对骨盆的位置（18 维）加骨盆速度（3 维）。
   - 窗口：41 帧（2 s），中心对齐。
   - 结构：卷积编码出 K = 4 条潜曲线，FFT 求频率 f、振幅 a、偏置 b，线性层加 atan2 求相位 φ；按 a·sin(2π(f·T − φ)) + b 重建曲线，再卷积解码回特征。
   - 用法：只在 train GT 上训练，滑窗得到逐帧相位向量 P(t) = a·(sin 2πφ, cos 2πφ)。
2. **步态解码器 G**
   - 输入：P(t)、本人朝向系下的骨盆速度、动作标签、腿长；用时间卷积看前后几帧。
   - 输出：6 段骨的单位方向（左右大腿、小腿、脚），从髋按骨长做正向运动学（FK），因此骨长误差为 0；另输出 4 个着地 logit。
   - 训练：GT 相位 + GT root。损失为腿关节 L2、着地 BCE（GT 着地标签）、GT 着地帧世界脚速平方（支撑脚不动）。
3. **相位预测器 F**
   - 输入：观测 10 帧的腿部特征、动作标签、主体预测的未来骨盆速度（训练时用 GT 加噪声，推理时用 BR）。
   - 输出：
     - 当前相位 φ0：每通道一个 (sx, sy)，用 atan2 得到；
     - 未来 50 帧的频率 f(t) 与振幅 a(t)：低阶 DCT 系数，经 softplus。
   - 相位积分：φ(t) = φ0 + Σ f / 20。
   - 损失：
     - 振幅 L2；
     - 频率 L2；
     - 相位圆周损失 a_gt·(1 − cos 2π(φ̂ − φ_gt))；
     - 自洽支撑：G 冻结，用预测相位解码出腿，在 G 自己给出的清晰着地帧上，惩罚世界脚速。这一项只能改相位快慢和振幅，不能改 G，所以不会把脚速整体压低，而是推动"步频与骨盆速度匹配"。
   - 不对 F 的输出直接施加腿部 L2，避免它为对冲相位不确定而缩小振幅。
4. **推理流程**：BR:ode0 给出 root、髋和上半身；F 预测相位；G 解码腿；FK 拼回完整骨架。全部是训练出来的网络，没有阈值、没有规则。

## 分阶段与预登记

全部在 H-val 上进行，不读 test。

### 第 0 阶段：可行性（只训练 PAE / G / F，不重训 BR，挂在 BR seed0 上）

| 诊断 | 设置 | 用途 |
|---|---|---|
| S0-1 | GT 相位 + GT root | oracle：表示上限 |
| S0-2 | 预测相位 + GT root | 只看相位预测本身 |
| S0-3 | 预测相位 + BR 的 root，完整推理 | 候选 PGait |

- **S0-1 继续条件**：步数 ≥ 2.0 且滑行帧比 ≤ .06。不满足说明流形或 G 表达不了步态，停下来修表示，不往后做。
- **S0-3 判定（候选 vs BR:ode0 不加规划，seed0）**：
  - 可采纳候选，须同时满足：
    - 滑行帧比 ≤ .06；
    - 步数 ≥ 1.60；
    - mpjpe ≤ 1.005 × BR（.16996）；
    - 护栏：xyz_mse ≤ 1.02×、jerk ≤ 24.5、穿地 ≤ BR + .01、骨长 ≤ 1e-5、四肢摆动 gate、接触前超额后退 ≤ 1.1×、漏接触 ≤ 1.1×；
    - 抽帧目视：脚印成簇、无弓步、无抖动。
  - 部分有效：滑行 ≤ .10 且步数 ≥ 1.39，护栏全过。
  - 否则无效。
- mpjpe 只允许 +0.5%，比前几轮的 1.01× 更严，因为用户要求 mpjpe 越低越好。如果 mpjpe 下降，单列报告。

### 第 1 阶段（第 0 阶段可采纳后才做）

- 模块种子 0/1/2 分别挂在 BR seed 0/1/2 上，按 3 seed 均值复核同一判定。
- 再做端到端：把 F 和 G 作为 BR 的腿流联合训练，使主体去噪器也能利用步态信息，目标是让 mpjpe 下降。
- 原协议 test 只在用户确认后评一次。

### 第 2 阶段（设想）

把相位流形扩展到全身，让手臂摆动与步态同相，针对 1.2–2 Hz 摆动只有 GT 26% 的问题。

## 风险

- NTU 序列很短（中位 72 帧），步行人只占约 30%，PAE 可能学不到稳定相位。S0-1 先检验这一点。
- 相位在 1 s 之后难以预测。提交到某个相位会让腿的误差变大，但腿只有 6 个关节，规划层的经验是 +0.3%。
- 训练时 G 和 F 看到的是 GT root，推理时是 BR root：BR 的 root 更平滑，速度偏小。S0-2 和 S0-3 的差距会显示这个影响，必要时改用 OOF 或联合训练。
- 两人交互问题（#194 走错方向、手没碰到就躲）不在本模块范围内。
